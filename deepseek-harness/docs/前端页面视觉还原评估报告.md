# 前端页面视觉还原评估报告

- 文档性质：静态评估报告（预评估），不包含任何代码修改
- 评估对象：`images/shuziyuangong.png`（随身秘书 · 数字员工能力中心页面设计稿）
- 目标系统：deepseek-harness Web/桌面客户端（React 18 + Vite + CSS Modules，`apps/web`）
- 评估日期：2026-10-05
- 文档语言：中文

---

## 1. 报告概述

### 1.1 背景与目标

项目根目录 `images/` 文件夹下存在一张 UI 设计稿 `shuziyuangong.png`，其内容为一款面向中国金融/银行垂直领域的 B2B 企业级 SaaS 产品页面——「随身秘书 · 数字员工能力中心」。该设计稿展示的是一个**能力目录（Catalog）页面**：左侧导航 + 顶部页面头部 + 分类筛选栏 + 四列响应式卡片网格。

本报告对该设计稿进行一次全面的图片识别与视觉分析，并基于当前 deepseek-harness 前端（Web 客户端）的实际架构，对「将现有前端页面修改为与设计稿视觉一致」这项工作进行**预评估**。评估结论以工时估算、风险清单与实施路线图的形式给出，供排期与决策使用。

### 1.2 评估范围

- 本次评估覆盖一个页面级别（能力目录主视图）的视觉还原工作；
- 设计稿中提及但未展开的「数据看板」「管理驾驶舱」等菜单页不在本次还原范围内；
- 不评估后端 API / 会话数据模型 / 插件运行时能力，仅评估前端表现层（UI 组件、布局、交互、样式、本地化）。

### 1.3 关键结论摘要

| 维度 | 结论 |
| --- | --- |
| 整体可行性与架构匹配度 | 高。新增面板的标准路径（keyed `main` slot + `sidebar.panellist` 注册）在仓库中已有成熟先例 |
| 组件复用率 | 中高。输入框、分段选择器、胶囊、标签、按钮、图标、主题令牌等原语齐全；**卡片、网格、收藏（星标）需新建** |
| 最大技术缺口 | 卡片式目录组件（先例为 `PluginCard`）、星标收藏持久化、侧边栏分组能力 |
| 预估总工时 | 约 48～80 人时（6～10 人日，单人全职口径），见第 8 章 |
| 主要风险 | 卡片/收藏无现成实现、暗色主题双端映射、i18n 强制双语、窄窗口响应式退化、视觉细节还原精度 |
| 是否需改核心架构 | 否。不触碰 `agent-loop`、不修改 `AppFrame` 三栏骨架，全部通过插件化槽位实现 |

## 2. 设计稿识别与分析

### 2.1 页面性质

设计稿为一张浅色主题的企业级 B2B 后台页面，产品名为「随身秘书」（英文化副标题「数字员工」）。页面为**能力发现/目录型视图**：用户通过分类浏览 AI 专家（数字员工）并点击「使用」发起协作。从文案（授信审查、反欺诈、网点运营、话术分析）可判断业务场景聚焦银行/金融风控与客户服务垂直领域。

### 2.2 三层信息架构

| 层级 | 内容 | 作用 |
| --- | --- | --- |
| L1 全局导航 | 左侧固定侧边栏（品牌 Logo + 菜单列表 + 用户资料/退出） | 全局功能切换 |
| L2 页面级筛选 | 面包屑、页面标题、副标题、搜索框、专家/专家团切换、排序（综合/最热/最新）、分类页签（全部/客户服务/风险管理/运营支持/产品营销/数据管理） | 目录收敛 |
| L3 内容展示 | 四列响应式卡片网格，每张卡片含圆形字符图标、标题、描述、标签胶囊、收藏星标、「使用」按钮 | 能力展示与操作入口 |

### 2.3 视觉元素清单

| 区域 | 元素 | 识别要点 |

| 侧边栏 | 分隔线 | 横向分隔符，将顶部功能与底部管理区隔开 |

| 头部 | 面包屑 | 「随身秘书 · 能力中心」 |
| 头部 | 标题区 | 大号加粗标题「数字员工」+ 一行副标题说明 |
| 头部 | 搜索框 | 右对齐，占位文案「搜索专家名称或简介」 |

| 卡片区 | 卡片 | 12+ 张，结构一致：圆形字符角标、标题、收藏星标（右上角，描边黄色）、「使用」按钮、两行描述、2~3 个标签胶囊 |

| 风险管理类卡片 | 紫 | `#A855F7 / #9333EA` |

色彩设计特点：**按业务域进行语义配色**（蓝=客户、紫=风险、青=产品/数据），帮助用户建立认知映射；整体为扁平化 + 1px 细边框（`#E5E7EB`）设计，无明显投影体系。

### 2.5 字体与排版

- 字体：系统中文字体栈（PingFang SC / Microsoft YaHei 类），标题层级明显；
- 字号层级：页面标题约 24px → 卡片标题约 16px → 正文约 14px → 标签约 12px；
- 圆角：卡片 8~12px、胶囊 16~20px、图标/头像全圆角；
- 间距：基于 4px 网格（4/8/12/16/24/32），卡片区间距约 24px。

### 2.6 与当前产品定位的契合度

「随身秘书」的定位与本仓库 Web 客户端（AI 个人助理/会话型客户端）高度吻合。设计稿中的「数字员工」本质是「可一键使用的一组 AI 专家能力」，与本项目"插件/能力组合"的产品模型在概念上可对应。因此本次还原不是把现有聊天界面推倒重来，而是在**现有三栏壳框架内新增一个目录型主面板**，视觉风格向设计稿对齐。

## 3. 页面布局复杂度分析

### 3.1 整体布局复杂度评级：中等

设计稿布局为「固定侧边栏 + 主内容区」的两栏结构，主内容区内部自上而下为头部、筛选栏、卡片网格三个纵向分区，无嵌套复杂布局、无图表、无数据表格。布局本身不构成瓶颈，复杂度主要来自**内容区的自适应与筛选态的联动**。

| 子区域 | 布局复杂度 | 说明 |
| --- | --- | --- |
| 侧边栏 | 低 | 现有 `AppFrame` 已提供三栏网格与侧边栏宽度拖拽，侧边栏为插件化注册；缺口是**分组能力**（当前面板列表为扁平结构） |
| 头部 | 低 | 单行布局，标题 + 右对齐搜索框，CSS Flex 即可完成 |
| 筛选栏 | 中 | 三组控件（主切换/排序/分类页签）横向排列，选中态联动多、状态源多，需统一状态模型 |
| 卡片网格 | 中高 | 四列响应式网格（`repeat(auto-fill, minmax(280px, 1fr))` 思路），需覆盖窄窗口降列行为与卡片内多元素排版 |
| 用户资料区 | 低 | 现有 `ui-settings-account` 已有头像组件，可复用 |

### 3.2 布局层面对现有壳框架的影响：无破坏性改动

`AppFrame`（`packages/client/ui-layout/src/client/AppFrame.tsx`）以 `grid-template-columns` 组织 侧边栏 | 主列 | 右栏 三轨，主列通过 `MainPanel` 渲染 `'main'` keyed slot。新增目录页**只需注册一个新的主面板 key**，无需修改三栏网格、拖拽手柄、列宽解算（`columns.ts`）等既有逻辑。

## 4. 视觉元素识别与实现难度评估

> 评级说明：低=现有原语直接组合可完成；中=需新建业务组件（有先例参照）；高=需新建机制或显著扩展基础能力。

| 设计稿元素 | 识别描述 | 可复用组件/机制 | 需新建内容 | 实现难度 |
| --- | --- | --- | --- | --- |
| 山形品牌图标 | Logo + 品牌文字 | `ui-sidebar` 品牌行已有品牌渲染位 | 若品牌图标不同则需新 SVG 图标 | 低 |
| 侧边栏菜单分组 | 顶部组/分隔线/底部组 | `SidebarRoot` 面板列表（扁平） | **面板分组与分隔线机制**（扩展 `sidebar.panellist` 注册项） | 中 |
| 选中菜单态 | 浅灰圆角底 `#F3F4F6` | `ui-sidebar` 已渲染选中态 | 仅样式对齐 | 低 |
| 用户资料/退出 | 头像 + 姓名 + 退出 | `ui-settings-account`（`AccountAvatar.tsx`） | 需要新的底部槽位挂载（当前设置入口在底部已存在） | 低 |
| 面包屑 | 「随身秘书 · 能力中心」 | 无现成面包屑组件 | 简易面包屑文本组件（两级即可） | 低 |
| 页面标题+副标题 | 24px 标题 + 说明文案 | CSS Modules + 主题字体 | 无 | 低 |
| 搜索框 | 右对齐、带占位文案 | `ui-primitives` 的 `Input`（先例：`TaskManagerPage` 搜索） | 无 | 低 |
| 专家/专家团切换 | 深色填充选中 / 浅色未选中 | `SegmentedControl` / `SegmentedTabs` | 无 | 低 |
| 排序项 | 综合/最热/最新 单选 | `SegmentedControl` | 无 | 低 |
| 分类页签 | 蓝下划线激活 | `SegmentedTabs` / `Pill` | 无 | 低 |
| 卡片 | 圆角色标 + 标题 + 描述 + 标签 | 先例：`ui-settings-plugins` 的 `PluginCard`；`Tag`（8 种 tone） | **通用目录卡片组件**（新建于特性包，按需提升至 `ui-primitives`） | 中 |
| 圆形字符角标 | 中文单字 + 业务色底 | `ui-primitives` 图标体系 | 按语义色生成字符角标组件 | 中 |
| 收藏星标 | 右上角描边/填充切换 | 无先例 | **星标按钮 + 收藏状态管理**（store + localStorage 持久化） | 中高 |
| 「使用」按钮 | 深色徽标式按钮 | `ui-primitives` `Button` | 无（注意与设计稿「仅首个卡片显示」的交互差异，见 5.5） | 低 |
| 标签胶囊 | 2~3 个小圆角标签 | `Tag`（胶囊样式） | 无 | 低 |
| 四列响应式网格 | `repeat(auto-fill, minmax(280px,1fr))` | CSS Grid 原生能力 | 网格容器样式 + 降列断点 | 中 |
| 空态/加载骨架 | 目录为空、加载中 | 无现成骨架屏 | 卡片骨架屏 + 空态组件 | 中 |
| 语义配色（5 色系） | 蓝/紫/青 等业务域配色 | `--dsw-static-*` / `--dsw-alias-*` 令牌 | **业务语义色令牌扩展**（须遵守禁字面颜色规范，映射到主题令牌） | 中 |

## 5. 交互功能实现复杂度

### 5.1 交互行为清单与复杂度

| 交互 | 触发/反馈 | 复杂度 | 实现要点 |
| --- | --- | --- | --- |
| 侧边栏面板切换 | 点击菜单项切换主面板 | 低 | 走 `ctx.layout.selectPanel(id)`，现有机制，无需开发 |
| 搜索过滤 | 输入即时过滤卡片列表 | 中 | 组件本地 `useState` + 防抖；先例 `TaskManagerPage` |
| 专家/专家团切换 | 主视图切换 | 中 | 需两套数据源/两组筛选态，状态模型需抽象 |
| 排序切换 | 综合/最热/最新重排 | 低 | 纯前端排序（评分/热度/创建时间字段来自数据层） |
| 分类页签筛选 | 按业务域过滤 | 低 | 与搜索、排序组合为单一筛选谓词 |
| 收藏星标 | 点击切换收藏，持久化 | 中高 | `defineStore` 状态 + localStorage 持久化（仓库有多个持久化先例）；收藏反馈（填充态 + Toast） |
| 「使用」按钮 | 进入协作/发起任务 | 中 | 触发既有「新建任务」/会话流转能力，属功能接缝，需产品侧确认 |
| 卡片悬停态 | 悬停反馈（投影/描边） | 低 | CSS 悬停态即可；设计稿本身为扁平风格，交互增强属建议项 |

### 5.2 状态管理方案

- **页面内临时状态**（搜索词、选中分类、排序）：组件本地 `useState`，与 `TaskManagerPage` 一致；
- **跨重挂载/全局共享状态**（收藏集合）：`defineStore`（`packages/client/store`），先例众多；
- **持久化**：localStorage（仓库先例：`ui-conversation`、`ui-sidebar-right/persistence.ts`、`ui-schedule/recent-time-zones.ts`）。仓库**无 URL query 持久化先例**，不建议为目录页引入路由式状态。

### 5.3 交互复杂度总体评级：中等

所有交互均为常规前端交互，不涉及拖拽、实时协作、图表联动等高级模式。真正的工作量集中在**筛选状态组合**（专家/专家团 × 排序 × 分类 × 搜索）与**收藏持久化**两处。

## 6. 技术栈匹配度分析

### 6.1 当前前端技术栈（已确认事实）

| 层面 | 现状 |
| --- | --- |
| 框架 | React 18 + TypeScript（strict），Vite 构建 |
| 样式方案 | **CSS Modules**（`*.module.css` + `clsx`），**禁字面颜色、禁 Tailwind、禁第三方组件库** |
| 主题 | 双主题设计令牌：`--dsw-static-*`（静态色板）+ `--dsw-alias-*`（语义别名），亮/暗双端在 `design-platform.css`，默认跟随系统 |
| 布局壳 | `AppFrame` 三栏网格 + keyed slot 渲染（`ui-layout`） |
| UI 原语 | `ui-primitives`：`Button`、`Input`、`SegmentedControl`、`SegmentedTabs`、`Pill`、`Tag`、`Menu`、`Tooltip`、`HoverCard`、`Toast`、`Modal`、`Avatar`、图标体系等 |
| 本地化 | `packages/client/locale`，**中文为键集源**，en 缺键即编译错误；`verify-client-ui-i18n` 门禁禁止硬编码文案 |
| 面板扩展 | keyed `main` slot + `sidebar.panellist` 注册，先例 `ui-plugin-manager`（PANEL_ID `'plugins'`）、`ui-schedule`（`'schedules'`） |
| 测试 | vitest（组件，jsdom）+ Playwright（web e2e，`apps/web/tests`）+ recorded-session 快照 |

### 6.2 逐项匹配度矩阵

| 设计稿需求 | 技术栈支持 | 匹配度 | 缺口 |
| --- | --- | --- | --- |
| 四列响应式卡片网格 | CSS Grid 原生 | 高 | 仅需新建网格样式 |
| 卡片组件 | 无通用 Card，有 `PluginCard` 先例 | 中 | 特性包内新建卡片组件 |
| 分段切换/页签 | `SegmentedControl`/`SegmentedTabs`/`Pill` 齐备 | 高 | 无 |
| 搜索框 | `Input` 齐备 | 高 | 无 |
| 标签胶囊 | `Tag`（8 tone）齐备 | 高 | 需按业务域映射 tone |
| 星标收藏 | 无先例 | 低 | 需新建按钮 + store + 持久化 |
| 品牌色对齐 | `--dsw-static-deepseek-500: rgb(65,118,230)` 与设计稿 `#3B82F6` 接近但不一致 | 中 | 需要决策：新建品牌/语义令牌或接受近似 |
| 浅色页面观感 | 亮色主题完整支持 | 高 | 需同步实现暗色变体 |
| 本地化 | i18n 强制双语 | 中 | 所有新文案须同时维护 zh/en 字典 |
| 中文字体 | `brand-font.css` 仅含 Montserrat（拉丁），中文字体依赖系统栈 | 中 | 跨平台中文字体渲染差异（见 7.3） |

### 6.3 架构层面适配结论

新增目录页完全走**插件化标准路径**，与仓库既定架构兼容：

1. 新建特性包 `packages/client/ui-<catalog>`，在 `apply()` 注册 `'main'` keyed slot（PANEL_ID）；
2. 注册 `sidebar.panellist` 侧边栏项；
3. 登记进 `packages/bundle/web-app/cordis.patch.yml` 与该 bundle 的 `package.json`（`packages/client/AGENTS.md`「New plugin package checklist」）。

**不需要**修改 `agent-loop`、`AppFrame`、会话模型或架构文档。

## 7. 潜在兼容性问题

| 编号 | 问题 | 影响 | 处理建议 |
| --- | --- | --- | --- |
| C1 | 侧边栏面板列表为**扁平结构**，设计稿要求分组 + 分隔线 + 底部管理区 | 需扩展 `sidebar.panellist` 注册协议（增加 group/divider 元数据），属于对现有注册机制的兼容性扩展 | 以向后兼容方式扩展协议（旧注册项无 group 字段时不分组），需过代码评审 |
| C2 | 四列网格在**窄窗口**退化 | Web 客户端窄宽度自动折叠侧边栏（`SIDEBAR_AUTO_COLLAPSE`）；桌面端小窗下 4 列不可用 | 用 `repeat(auto-fill, minmax(280px,1fr))` 天然降列；平板 2 列、手机 1 列；必要时在 280px 阈值以下单列 |
| C3 | **暗色主题**下设计稿观感 | 设计稿为浅色；亮/暗双主题切换后卡片、筛选栏、语义色需双端 token 映射 | 所有新组件只用 `--dsw-alias-*` 语义令牌，禁止写死 `#FFFFFF`/`#F9FAFB`；暗色下走现有 `data-ds-dark-theme` 变体 |
| C4 | **中文字体**跨平台差异 | `brand-font.css` 仅 Montserrat（拉丁）；中文回退到 PingFang SC（macOS）/微软雅黑（Windows），行高与字形观感不同 | 不引入 web font 中文方案（体积与性能不可行），通过 `--dsw-font-family` 系统栈 + 行高容差处理；还原验收按目标主平台优先 |
| C5 | **禁字面颜色**规范 | 设计稿提取的 `#3B82F6`、`#F9FAFB` 等不能直接写入样式 | 全部映射为新增/既有令牌（业务语义色扩展 `--dsw-alias-*`）；涉及 `ui-theme` 的令牌变更需走主题包评审 |
| C6 | **i18n 强制双语** | 所有新文案（标题、副标题、分类名、标签、占位符、空态）须同步维护 zh/en 字典，缺键导致编译失败 | 文案以中文为键集源，en 同步翻译；分类与标签文案数量多（12+ 卡片 × 2~3 标签），建议先收敛字段再翻译 |
| C7 | **可访问性**：纯颜色区分业务域 | 色盲用户无法仅凭颜色区分卡片类别 | 增加图标/字符角标差异（设计稿已有字符角标，天然缓解）；聚焦态、键盘导航需补齐 |
| C8 | 桌面端（`apps/desktop`）窗口内渲染 | 目录页在桌面小窗下与 web 同构，受 C2 影响 | 纳入桌面端手工验收；复用同一套响应式 |
| C9 | **快照/测试要求** | 产品可见输出变化需 recorded-session 快照；组件需 vitest + Playwright 覆盖 | 按「计划单测、e2e、快照覆盖」的仓库要求随变更提交测试，工作量已计入第 8 章 |
| C10 | 设计稿「使用」按钮仅首卡可见 | 交互不一致（其余卡片悬停才出按钮，或为设计瑕疵） | 还原前先与产品确认：统一常驻 or 统一悬停显示；避免照抄单例 |
| C11 | 品牌蓝偏差 | 现有品牌令牌与设计稿 `#3B82F6` 不完全一致 | 决策：建立新的目录页语义色令牌（推荐，不污染全局品牌色）或在产品层面统一品牌色 |

## 9. 技术注意事项

以下为实施阶段必须遵守的仓库级约束与建议，按优先级排列：

1. **插件化注册，禁止改核心**：新页面只通过 keyed `main` slot 与 `sidebar.panellist` 注册实现；不修改 `agent-loop`、`AppFrame`、列宽解算等核心逻辑，否则需同步更新 `docs/architecture.md`。
2. **样式三禁**：禁止字面颜色、禁止第三方组件库、禁止 Tailwind；所有新样式使用 CSS Modules + 既有/新增 `--dsw-*` 令牌。新增令牌集中在 `ui-theme`，并补齐暗色变体。
3. **文案本地化**：新文案全部入 `packages/client/locale` 的双语字典（zh 为键集源，en 缺键编译失败）；分类/标签等业务词表先统一收敛，避免后续反复翻译。
4. **测试随行**：新组件补 vitest（jsdom）单测；Web 集成用 Playwright；产品可见输出变化按仓库要求更新 recorded-session 快照。任何新工具面板的 UI 呈现按仓库规范在特性包内先定义 presenter。
5. **状态分层**：页面内状态用组件本地 `useState`；收藏等跨挂载状态用 `defineStore` + localStorage；不引入 URL 路由式状态（仓库无先例）。
6. **可访问性**：区分业务域不能仅靠颜色（结合字符角标差异）；补齐键盘导航与聚焦态；收藏星标提供 `aria-pressed`/替代文本。
7. **响应式自检**：以 280px 最小卡宽做 `auto-fill` 网格；在窄窗口（侧边栏自动折叠阈值）与桌面小窗下各验收一次。
8. **交互一致性**：先与产品确认「使用」按钮的显隐策略（常驻/悬停），避免照抄设计稿中仅首卡可见的单例。
9. **新包清单**：按 `packages/client/AGENTS.md`「New plugin package checklist」登记 bundle patch、包依赖与 workspace 元数据。
10. **数据接缝**：卡片数据源先以特性包内轻量数据/假数据接入，业务字段（评分/热度/标签/分类）留类型化接口，后续替换真实来源时不影响 UI。

## 11. 实施路线建议（分阶段）

**阶段 A（MVP 页面，约 35~40 人时）**
- 新建特性包与面板注册；页面头部 + 筛选栏 + 卡片网格（浅色主题）；
- 卡片数据用类型化假数据；搜索/排序/分类本地状态；
- i18n 双语字典、组件单测与 Playwright 冒烟、桌面端验收。

**阶段 B（交互与体验，约 20~30 人时）**
- 星标收藏（store + localStorage 持久化 + 反馈）；
- 侧边栏分组/分隔线协议扩展；空态与加载骨架；
- 暗色主题全量变体；可访问性补齐。

**阶段 C（产品化，按需）**
- 真实数据源接入、收藏跨端同步、专家团视图、数据看板/管理驾驶舱等后续页面按同一套模式复制扩展。

## 12. 结论

- 设计稿为结构清晰、组件复用度高的**企业级能力目录页面**，业务域语义配色与卡片结构是本仓库可直接落地的形态；
- 现有 Web/桌面客户端架构（React 18 + CSS Modules + 设计令牌 + 插件化面板注册）与设计稿**技术匹配度高**，新增页面走既有标准路径，无需改动核心架构；
- 主要工作量集中在**四个新建点**：通用目录卡片组件、星标收藏持久化、侧边栏分组协议、业务语义色令牌（含暗色变体）；
- 预计总工时约 **60～106 人时（中位数约 80 人时 / 10 人日）**，MVP 版可压缩至约 35~40 人时；
- 主要风险均可用「向后兼容扩展 + 令牌化 + 数据解耦 + 范围冻结」四项策略可控。

综上，本次视觉还原修改工作**技术上可行、架构上低侵入**，建议按第 11 章的三阶段路线推进。
