# 前端改造计划文档

- 适用范围：`images/design` 前端工程（Vue3 + TypeScript + Element Plus + Vite）。
- 设计稿：`docs/2.0` 前序产出、`images/shuziyuangong.png` 数字员工能力中心视觉体系。
- 后端依据：`docs/2.0/后端接口文档.md`（deepseek-harness-admin，Spring Boot，端口 8080，接口前缀 `/api`）。
- 本文档约定：页面改造为 **1:1 还原设计稿**，同时将现有本地 mock 数据切换为真实后端接口，视觉与接口双对齐。

## 一、改造页面清单

| # | 页面 | 路由 | 当前实现 | 本轮改造范围 | 验收标准 | 排期 |
|---|---|---|---|---|---|---|
| P1 | 登录页 | `/login` | 本地 localStorage 校验 | 视觉保持；鉴权切换为 `POST /api/auth/login`；字段与校验对齐接口 | 登录成功拿到 token 并跳转；错误按 `code` 提示 | T0（后端就绪即开始） |
| P2 | 注册页 | `/register` | 本地账号写入 | 视觉保持；切换为 `POST /api/auth/register`；字段校验对齐接口 | 注册成功跳登录并预填用户名；重复账号/校验失败有正确提示 | T1 |
| P3 | 数字员工列表页 | `/employees` | 本地 mock 全量卡片 | 视觉保持；切换为 `GET /api/digital-employees` 分页；数据字段映射 | 卡片字段正确渲染；分页/搜索/排序可用；空态与加载态正常 | T2 |
| P4 | 数字员工对话页 | `/employee/:id` | 本地 mock 会话 + 流式 | 视觉保持；接入会话列表/消息/对话三接口；流式 mock 改为接口一次性返回 | 会话历史加载、消息渲染、发送/延续会话正确、切换会话正常 | T3 |
| P5 | harness 对话页 | `/chat` | 本地 mock，无后端对应 | 仅视觉还原，**不参与接口化改造** | 视觉与稿对齐，交互正常 | T0 并行 |

> 说明：P5（deepseek harness 对话页）对应 agent harness 运行逻辑，deepseek-harness-admin 后端不提供其对话接口，故本轮不做接口接入，保留现有实现，仅视觉在改造中顺带校准。

## 二、接口清单筛选

按后端接口文档逐条筛选。**仅保留本项目实际调用**的 8 个接口，其余全部排除。

### 2.1 保留接口

| 模块 | 方法 | 路径 | 鉴权 | 用途 |
|---|---|---|---|---|
| 认证 | POST | `/api/auth/register` | 公开 | 注册（P2） |
| 认证 | POST | `/api/auth/login` | 公开 | 登录拿 token（P1） |
| 认证 | POST | `/api/auth/logout` | 已认证 | 退出（P1） |
| 数字员工 | GET | `/api/digital-employees` | ADMIN | 列表分页（P3） |
| 数字员工 | GET | `/api/digital-employees/{id}` | ADMIN | 详情（P4） |
| 预览对话 | POST | `/api/digital-employees/{id}/chat` | ADMIN | 发起/延续会话（P4） |
| 预览对话 | GET | `/api/digital-employees/{id}/conversations` | ADMIN | 会话历史分页（P4） |
| 预览对话 | GET | `/api/digital-employees/{id}/conversations/{conversationId}/messages` | ADMIN | 会话消息（P4） |

### 2.2 排除接口及原因

| 接口 | 原因 |
|---|---|
| `GET /api/health`、`GET /actuator/health` | 运维探活，前端非业务所需 |
| `POST/GET /api/knowledge-bases`、`/api/knowledge-bases/{id}`、`.../{id}/reprocess` | 知识库为管理端后台配置，不在登录注册/数字员工查看/对话三模块范围 |
| `POST/GET /api/skills`、`/api/skills/{id}` | Skill 管理属后台配置，前端只读员工时无需 |
| `POST /api/digital-employees`、`.../{id}/publish`、`.../{id}/rollback` | “数字员工查看模块”为只读，创建/发布/回滚属管理端编辑，前端不体现 |

### 2.3 统一对接约定

- 业务成败以响应体 `code == "SUCCESS"` 判断，**不依赖 HTTP 状态码**（业务恒为 HTTP 200）。
- 受保护接口请求头携带 `Authorization: Bearer <token>`、`Content-Type: application/json`。
- 公共错误码统一处理：`AUTH_UNAUTHORIZED` → 清理 token 跳登录；`RESOURCE_FORBIDDEN` → 提示无权限；`VALIDATION_FAILED` / 其余业务错 → 展示 `message`。
- 对接实现位于 `src/api/request.ts`（axios 实例，`baseURL` 按环境配置指向 8080）与各模块 api 文件。

## 三、逐页面接口调用与数据规则

### 3.1 登录页 P1

**调用的接口**：`POST /api/auth/login`

请求体：
| 字段 | 类型 | 必填 | 规则 |
|---|---|---|---|
| `username` | string | 是 | 非空 |
| `password` | string | 是 | 非空 |

成功响应 `data`：`{ token: string, user: { id, username, role } }`。

**处理规则**
1. 重命名现有表单 `account` → `username`，同时 **password ≥ 8**（接口要求 8-64）。
2. 前端本地校验仅做非空与长度兜底，最终以服务端 `VALIDATION_FAILED` 为准。
3. 成功：本地存 `token` + `user`（key 建议 `ssms:token` / `ssms:user`），路由守卫据此放行；跳转 `redirect` 参数或 `/chat`。
4. 失败映射：`AUTH_INVALID_CREDENTIALS`（按 message 区分 账号不存在/密码错误/锁定）、`ACCOUNT_DISABLED`、`VALIDATION_FAILED` → 用 `ElMessage.error(响应 message)`。
5. 退出登录：调用 `POST /api/auth/logout` 后清理本地 token 并跳 `/login`（退出失败也清理本地，保证可登出）。

### 3.2 注册页 P2

**调用的接口**：`POST /api/auth/register`

请求体：`{ username, password }`，**不接受角色字段**（服务端固定 USER）。

**处理规则**
1. 表单字段 `account` → `username`；校验对齐接口：`username` 仅字母/数字/下划线、长度 3-32；`password` 长度 8-64。
2. 前端保留二次确认密码校验（仅前端，不送后端）。
3. 成功：接口只返 `user`（无 token），故注册成功后跳转到 `/login` 并预填 `username`，由用户在登录页完成登录拿 token。
4. 失败映射：`USERNAME_EXISTS`（账号已存在）、`VALIDATION_FAILED` → 展示 message。

### 3.3 数字员工列表页 P3

**调用的接口**：`GET /api/digital-employees`

查询参数：`page`（默认 1）、`size`（默认 10）。响应为 `PageResult`：`{ page, size, total, items }`，`items[]` 为 `DigitalEmployeeResponse`。

`DigitalEmployeeResponse`：`{ id, name, description, systemPrompt, modelConfig, status, publishedVersion, skillIds, createdAt }`。

**字段映射（设计稿字段 → 接口字段）**

| 卡片要素 | 设计稿字段 | 数据来源 | 规则 |
|---|---|---|---|
| 圆图标底色 | `color` | 无接口字段 | 前端按 `id` 哈希或 `status` 派生业务色板 |
| 圆图标单字 | `iconChar` | 无接口字段 | 取 `name` 首字 |
| 标题 | 卡片标题 | `name` | 直接映射 |
| 描述 | `desc` | `description` | 两行截断 |
| 功能标签 | `tags` | 无接口字段 | 由 `skillIds` 派生能力名称或显示空态；无数据时隐藏标签组 |
| 使用角标 | `inUse` | 无接口字段 | 用 `status == "PUBLISHED"` 派生（已发布的视作“使用”） |
| 收藏星标 | `favorite` | 无接口字段 | 前端本地状态（localStorage），不影响后端 |

**处理规则**
1. 首次加载 `GET ?page=1&size=X`；滚动到底加载下一页追加 `items`，`total` 控制停止。
2. “专家/专家团”类型：接口无此概念。专家 = 全部；专家团 = 本地过滤 `status == "PUBLISHED"`。
3. 排序（综合/最热/最新）：接口无排序参数，前端本地对已加载集合排序（综合=接口原序；最热=已发布在前；最新=`id` 倒序）。
4. 搜索：接口无关键词参数，前端对已加载 `name`/`description` 本地过滤（如需服务端搜索，后续需后端加参数，本轮不做）。
5. 空态、加载骨架沿用现有组件。

### 3.4 数字员工对话页 P4

**调用的接口**
| 场景 | 接口 |
|---|---|
| 进入页面/刷新 | `GET /api/digital-employees/{id}` 校验存在或取标题 |
| 会话历史列表 | `GET /api/digital-employees/{id}/conversations?page&size` |
| 选中会话拉消息 | `GET /api/digital-employees/{id}/conversations/{conversationId}/messages` |
| 发送消息 | `POST /api/digital-employees/{id}/chat` |

**chat 请求体**：`{ message: string(≤4000), conversationId?: long }`
- `conversationId` 为空 → 服务端发起新会话；传入 → 延续该会话。
- 响应 `data`：`{ conversationId, reply, createdAt }`，**一次性返回完整回复，非流式**。

**角色映射**：`MessageResponse.role` `USER`/`ASSISTANT` → 前端气泡 `user`/`assistant`。

**处理规则**
1. 进入页面：调用详情接口，不存在或失败 → 返回列表并提示 `RESOURCE_NOT_FOUND`。
2. 左侧会话列表（复用现有 `ChatSessionSidebar` 概念）加载接口 18，选中会话时调接口 19 拉全部消息正序渲染。
3. 发送：先本地回显用户消息，调 chat 接口；成功用返回 `reply` 追加助手消息；**替换现有流式 mock 为一次性渲染**（可保留逐字动画作为视觉效果，但内容取自 `reply`）。
4. 新建会话：不带 `conversationId` 发送首条；服务端返回新 `conversationId` 并回填会话列表。
5. `CHAT_PROVIDER_NOT_CONFIGURED` / `CHAT_FAILED` → 按 message 提示，用户消息保留。

### 3.5 harness 对话页 P5

- 无对应后端接口，不做接口改动。仅校准视觉与设计稿一致。
- 现有会话、流式回复、设置抽屉均保留。

## 四、实施步骤、联调测试与验收

### 4.1 实施步骤（依赖后端就绪）

| 步骤 | 内容 | 依赖 |
|---|---|---|
| S1 | 前端 `request.ts` 统一：`baseURL` 指向后端、封装 200 但按 `code` 判成败、`AUTH_UNAUTHORIZED` 统一处理 | 后端部署可用 / 本地 8080 |
| S2 | P1 登录、P2 注册 接入；接通 token 存储与路由守卫 | 认证三接口 |
| S3 | P3 列表接入分页/映射/派生字段 | 员工列表接口 |
| S4 | P4 对话接入会话/消息/chat 三接口，替换流式 mock | 预览对话三接口 |
| S5 | 视觉逐项比对设计稿修正、响应式、空/加载态、错误态 | — |
| S6 | 全链路联调 + 回归 | 后端联调环境 |

> 注：后端若已就绪，S1-S4 可并行推进；各步骤完成后独立自测。

### 4.2 接口联调测试方案

以 `http://localhost:8080` 为基址，逐项验证：

1. **认证**：注册（新账号）→ 重复注册（`USERNAME_EXISTS`）→ 登录得 token → 错误密码（`AUTH_INVALID_CREDENTIALS`）→ 带 token 访问受保护接口成功 → `logout` 后访问受保护接口 `AUTH_UNAUTHORIZED`。
2. **列表**：登录后 `GET /api/digital-employees` 返回分页；`page=0`/超上限收敛；空数据空态；详情 404 → `RESOURCE_NOT_FOUND`。
3. **对话**：无 token 调 `chat` → `AUTH_UNAUTHORIZED`；发首条（无 `conversationId`）得到新会话；带 `conversationId` 延续；非法 `conversationId` → `会话不存在`；对话模型未配置 → `CHAT_PROVIDER_NOT_CONFIGURED`。

联调脚手架：逐接口用浏览器/curl 验证响应 `code`，再用前端页面走全流程（注册→登录→列表→对话→退出）。

### 4.3 验收标准

1. **视觉**：5 页面与设计稿在配色、字号、间距、圆角、阴影、交互一致，响应式在 ≥768px 下无错位。
2. **功能**：
   - 注册/登录/退出全链路可用，错误提示正确。
   - 数字员工列表分页、搜索、排序、类型切换、空态可用。
   - 数字员工对话的会话列表、消息加载、发送/延续、新建会话正确。
3. **接口规范**：全部请求按 §2.3 约定，以 `code` 判成败，未授权统一处理；无对 `HTTP 401/403` 的依赖。
4. **稳定性**：无死链、无跳转异常、无未捕获接口错误；接口失败时不白屏，有明确提示。
5. **回归**：P5 harness 页面既有功能无回归。

### 4.4 备注

- 设计稿字段与接口字段的差异（`color/iconChar/tags/favorite/inUse` 等）按 §3.3 前端派生/本地态处理，不新增后端字段，前后端对齐以此表为准。
- 本文档与《后端接口文档》保持同步；后端改接口需同步修订此处第 3 节与接口清单。
