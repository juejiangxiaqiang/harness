# deepseek-harness-admin 后端接口文档

## 一、文档说明

本文档基于对后端源码的全面扫描生成，描述管理后台服务的全部 HTTP 接口，内容与实现保持逐项一致。

- 适用服务：管理后台后端（Spring Boot）。
- 核心模块：认证、健康检查、知识库、Skill、数字员工、管理端预览对话、基础设施探活。
- 对接方：管理后台前端、运维探活、第三方集成。

## 二、全局通用约定

### 2.1 基础信息

| 项 | 说明 |
|---|---|
| 默认服务端口 | `8080`（可通过环境变量 `SERVER_PORT` 覆盖） |
| 接口前缀 | `/api` |
| 无 context-path | 所有接口相对服务根路径 |
| 内容协商 | 请求与响应均为 `application/json`（除文件上传接口使用 `multipart/form-data`） |
| 编码 | UTF-8 |

### 2.2 全局请求头约定

| 请求头 | 是否必填 | 说明 |
|---|---|---|
| `Authorization` | 受保护接口必填 | 认证凭证，格式 `Bearer <token>`；登录接口返回的 `token` 原样携带 |
| `X-Trace-Id` | 选填 | 请求追踪标识。若不传，服务端自动生成 UUID 并写入日志与响应；若传入则透传，保证全链路关联 |
| `Content-Type` | JSON 接口必填 | `application/json`；文件上传接口使用 `multipart/form-data` |

### 2.3 认证方式

- 采用基于数据库凭证的 **Bearer Token** 认证，非 JWT。
- 登录成功后服务端签发一次性原始 token（仅返回一次），数据库只保存其 SHA-256 哈希。
- 受保护接口在请求头携带 `Authorization: Bearer <token>`。
- 无需认证的白名单路径（精确匹配）：`/api/auth/register`、`/api/auth/login`、`/api/health`。
- 知识库、Skill 与数字员工管理操作（创建/发布/回滚）要求 `ADMIN` 角色；普通用户访问返回 `RESOURCE_FORBIDDEN`。
- 数字员工**浏览与对话**对已登录用户开放：普通用户（`USER`）仅可见/可对话**已发布（`PUBLISHED`）**数字员工，且响应裁剪内部配置（系统提示词、模型配置、Skill 关联）；访问未发布员工返回 `RESOURCE_NOT_FOUND`（不泄露存在性）。
- 未携带或携带无效凭证访问受保护接口返回 `AUTH_UNAUTHORIZED`。

### 2.4 统一响应格式

除 `GET /actuator/health`（Spring Actuator 原生格式，见 §6）外，**所有业务接口**（成功与失败）统一返回 HTTP 200 与如下结构：

```json
{
  "code": "SUCCESS",
  "message": "success",
  "data": {},
  "traceId": "a-b-c-d"
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `code` | string | 业务错误码，成功为 `SUCCESS`，失败为对应错误码（见 §2.5） |
| `message` | string | 提示信息，成功为 `success`，失败为面向客户端的中文描述 |
| `data` | object/null | 业务数据；无数据时返回 `null` |
| `traceId` | string | 本次请求追踪标识，与响应头 `X-Trace-Id` 一致 |

### 2.5 HTTP 状态码约定

> 重要：本项目业务成功与失败均以 **HTTP 200** 返回，业务结果由响应体 `code` 区分。前端与第三方对接须以 `code` 字段判断成败，而非 HTTP 状态码。下表同时列出由框架/容器在**进入业务处理前**可能产生的非 200 状态。

| HTTP 状态码 | 场景 |
|---|---|
| `200 OK` | 所有业务接口的成功与失败响应（统一结构，以 `code` 区分） |
| `400 Bad Request` | 请求体 JSON 无法反序列化、路径/参数格式错误等框架层异常（伴随错误码 `INTERNAL_ERROR`） |
| `404 Not Found` | 访问不存在的接口路径（`NoResourceFoundException` → 错误码 `RESOURCE_NOT_FOUND`） |
| `405 Method Not Allowed` | 接口存在但请求方法不符（框架默认） |
| `413 Payload Too Large` | 上传超过容器大小限制（默认 20MB，见 §3.1） |
| `415 Unsupported Media Type` | JSON 接口未携带 `Content-Type: application/json`（框架默认） |

### 2.6 全局业务错误码

| 错误码 | 含义 | 典型触发场景 |
|---|---|---|
| `SUCCESS` | 成功 | — |
| `AUTH_INVALID_CREDENTIALS` | 登录凭证错误 | 账号不存在、密码错误、登录失败次数超限被锁定 |
| `AUTH_UNAUTHORIZED` | 未登录或凭证无效 | 未携带凭证、凭证失效/过期/已吊销、账号不可用 |
| `USERNAME_EXISTS` | 账号已存在 | 注册或初始化管理员时账号重复 |
| `ACCOUNT_DISABLED` | 账号已禁用 | 登录账号状态非激活 |
| `RESOURCE_NOT_FOUND` | 资源不存在 | 知识库/Skill/数字员工/发布记录/会话不存在、接口路径不存在 |
| `RESOURCE_FORBIDDEN` | 无资源访问权限 | 普通用户访问管理接口（缺少 ADMIN 角色） |
| `VALIDATION_FAILED` | 参数校验失败 | 请求体字段校验失败、上传文件类型/大小/名称非法、Skill 不可用、发布记录不属于该数字员工、不可回滚非成功记录 |
| `KNOWLEDGE_BASE_PROCESSING` | 知识库正在向量化处理 | 对 UPLOADING/PROCESSING 状态知识库执行重新处理 |
| `KNOWLEDGE_BASE_NOT_READY` | 知识库尚未准备完成 | 关联非 READY 状态知识库到 Skill |
| `VECTOR_INDEX_FAILED` | 向量化或向量数据库写入失败 | Embedding 或向量写入异常（异步任务阶段） |
| `DIGITAL_EMPLOYEE_NOT_PUBLISHABLE` | 数字员工不满足发布条件 | 基础信息不完整、未关联可用 Skill、Skills 未关联可用知识库、历史版本引用的资源已失效 |
| `CHAT_PROVIDER_NOT_CONFIGURED` | 对话模型未配置 | 预览对话时 Spring AI 聊天模型 Bean 未装配 |
| `CHAT_FAILED` | 对话生成失败 | 调用对话模型异常 |
| `INTERNAL_ERROR` | 系统内部错误 | 未预期异常；仅记录日志不向客户端泄漏内部细节 |

### 2.7 分页约定

- 列表接口统一分页参数：`page`（页码，从 1 开始，默认 1）、`size`（每页条数，默认 10）。
- 单页上限 100；传入越界值由服务端收敛（page≥1，size 收敛到 [1,100]）。
- 响应 `data` 为分页对象：`{ "page":long, "size":long, "total":long, "items":[] }`。

### 2.8 上传约定（知识库）

- `Content-Type: multipart/form-data`。
- 表单字段：`file`（文件，必填）、`name`（知识库名称，可选，缺省取文件名主体）。
- 允许扩展名：`txt`、`md`、`pdf`、`docx`（小写，来自配置）；解析阶段仅 `.txt`/`.md` 可成功，`pdf/docx` 上传后可入库但会在向量化阶段解析失败并标记为 `FAILED` 且记录失败原因。
- 大小上限：默认 20MB（`spring.servlet.multipart.max-file-size=20MB`，与 `harness.storage.max-file-size-mb` 一致）。
- 文件名长度上限 255；知识库名称长度上限 128。

## 四、认证模块

### 接口 1：用户注册

- **路径**：`POST /api/auth/register`
- **鉴权**：公开（白名单）
- **请求头**：`Content-Type: application/json`

**请求体**：

| 字段 | 类型 | 必填 | 说明 | 校验规则 | 示例 |
|---|---|---|---|---|---|
| `username` | string | 是 | 登录账号 | 非空；仅字母/数字/下划线，长度 3-32 | `zhangsan` |
| `password` | string | 是 | 登录密码 | 非空；长度 8-64 | `secret123` |

注意：请求体**不接受角色字段**；服务端固定创建 `USER` 角色，公开注册无法自助提升管理员权限。

**成功响应（HTTP 200）**：`data` 为用户基本信息。

```json
{
  "code": "SUCCESS",
  "message": "success",
  "data": { "id": 1, "username": "zhangsan", "role": "USER" },
  "traceId": "abc"
}
```

**失败响应**：

| 错误码 | 说明 |
|---|---|
| `USERNAME_EXISTS` | 账号已存在（先查后插 + 唯一索引兜底并发） |
| `VALIDATION_FAILED` | 请求体校验失败，`message` 形如 `username: 用户名仅支持字母、数字、下划线，长度 3-32` |

---

### 接口 2：登录

- **路径**：`POST /api/auth/login`
- **鉴权**：公开（白名单）
- **请求头**：`Content-Type: application/json`

**请求体**：

| 字段 | 类型 | 必填 | 说明 | 校验规则 | 示例 |
|---|---|---|---|---|---|
| `username` | string | 是 | 登录账号 | 非空 | `zhangsan` |
| `password` | string | 是 | 登录密码 | 非空 | `secret123` |

**成功响应（HTTP 200）**：`data` 为 `{ "token": string, "user": UserResponse }`。`token` 仅返回一次，请妥善保存。

```json
{
  "code": "SUCCESS",
  "message": "success",
  "data": {
    "token": "a1b2c3d4e5f6...",
    "user": { "id": 1, "username": "zhangsan", "role": "ADMIN" }
  },
  "traceId": "abc"
}
```

**失败响应**：

| 错误码 | 说明 |
|---|---|
| `AUTH_INVALID_CREDENTIALS` | 账号不存在（`message`=`账号不存在`）、密码错误（`message`=`密码错误`）、登录失败次数过多被锁定（`message`=`登录失败次数过多，请稍后重试`） |
| `ACCOUNT_DISABLED` | 账号状态非激活 |
| `VALIDATION_FAILED` | 请求体校验失败 |

约定：默认连续失败 `maxLoginAttempts=5` 次锁定 `lockMinutes=15` 分钟（单机内存计数，可通过环境配置调整）；锁定期内仍返回统一的 `AUTH_INVALID_CREDENTIALS`，不暴露具体账号状态。

---

### 接口 3：退出登录

- **路径**：`POST /api/auth/logout`
- **鉴权**：已认证（不在白名单）；携带 `Authorization: Bearer <token>`
- **请求头**：`Authorization: Bearer <token>`、`Content-Type: application/json`
- **请求体**：无

**说明**：吊销当前凭证（按 token 哈希置为已吊销），重复退出幂等不报错。

**成功响应（HTTP 200）**：`data` 为 `null`。

```json
{ "code": "SUCCESS", "message": "success", "data": null, "traceId": "abc" }
```

**失败响应**：

| 错误码 | 说明 |
|---|---|
| `AUTH_UNAUTHORIZED` | 未携带或凭证无效 |

---

## 五、健康检查模块

### 接口 4：健康检查

- **路径**：`GET /api/health`
- **鉴权**：公开（白名单）
- **请求参数**：无

**成功响应（HTTP 200）**：`data` 为 `{ "status": "UP", "time": "<ISO-8601>" }`。

```json
{
  "code": "SUCCESS",
  "message": "success",
  "data": { "status": "UP", "time": "2026-10-12T10:30:00.123+08:00" },
  "traceId": "abc"
}
```

**失败响应**：正常无失败路径；深层依赖（MySQL、向量库）健康由 `/actuator/health`（接口 20）覆盖。

## 六、知识库模块（全部要求 ADMIN）

### 接口 5：上传知识库

- **路径**：`POST /api/knowledge-bases`
- **鉴权**：`ADMIN`
- **请求头**：`Authorization: Bearer <token>`、`Content-Type: multipart/form-data`

**表单参数**：

| 字段 | 类型 | 必填 | 说明 | 校验规则 | 示例 |
|---|---|---|---|---|---|
| `file` | File | 是 | 待上传文件 | 非空；扩展名 ∈ {`txt`,`md`,`pdf`,`docx`}（小写）；大小 ≤ 20MB | `guide.md` |
| `name` | string | 否 | 知识库名称 | 缺省取文件名主体；长度 ≤ 128 | `操作手册` |

**过程说明**：保存文件与元数据（状态 `UPLOADING`）后**自动异步触发向量化**；向量化成功进入 `READY`，解析失败经有限重试后进入 `FAILED` 并记录失败原因。客户端通过详情接口（接口 7）轮询状态。

**成功响应（HTTP 200）**：`data` 为知识库对象（初始状态通常为 `UPLOADING`）。

```json
{
  "code": "SUCCESS",
  "message": "success",
  "data": {
    "id": 5,
    "name": "操作手册",
    "status": "UPLOADING",
    "fileName": "guide.md",
    "chunkCount": 0,
    "vectorStore": null,
    "embeddingModel": null,
    "failureReason": null,
    "createdAt": "2026-10-12T10:30:00"
  },
  "traceId": "abc"
}
```

**失败响应**：

| 错误码 | 说明 |
|---|---|
| `VALIDATION_FAILED` | 文件为空、不支持的文件类型、文件大小超过上限、知识库名称超过 128 |
| `AUTH_UNAUTHORIZED` | 未登录或凭证无效 |
| `RESOURCE_FORBIDDEN` | 非 ADMIN 角色 |
| `413 Payload Too Large` | 超过容器 20MB 上限 |

---

### 接口 6：分页查询知识库列表

- **路径**：`GET /api/knowledge-bases`
- **鉴权**：`ADMIN`
- **请求头**：`Authorization: Bearer <token>`

**查询参数**：

| 字段 | 类型 | 必填 | 默认 | 说明 | 校验规则 |
|---|---|---|---|---|---|
| `page` | long | 否 | 1 | 页码 | 服务端收敛 ≥1 |
| `size` | long | 否 | 10 | 每页条数 | 服务端收敛至 [1,100] |

**说明**：知识库为全局共享资源，列表**不按创建人过滤**；按创建时间倒序。

**成功响应（HTTP 200）**：`data` 为分页对象。

```json
{
  "code": "SUCCESS",
  "message": "success",
  "data": { "page": 1, "size": 10, "total": 2, "items": [ ] },
  "traceId": "abc"
}
```

`items[]` 元素结构与接口 5 的 `data` 相同（`KnowledgeBaseResponse`）。

**失败响应**：仅鉴权类（`AUTH_UNAUTHORIZED` / `RESOURCE_FORBIDDEN`）。

---

### 接口 7：查询知识库详情

- **路径**：`GET /api/knowledge-bases/{id}`
- **鉴权**：`ADMIN`

**路径参数**：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | long | 是 | 知识库 ID |

**成功响应（HTTP 200）**：`data` 为 `KnowledgeBaseResponse`，结构同接口 5。

**失败响应**：

| 错误码 | 说明 |
|---|---|
| `RESOURCE_NOT_FOUND` | 知识库不存在（`message`=`知识库不存在`） |
| `AUTH_UNAUTHORIZED` / `RESOURCE_FORBIDDEN` | 未认证 / 非 ADMIN |

---

### 接口 8：重新处理知识库

- **路径**：`POST /api/knowledge-bases/{id}/reprocess`
- **鉴权**：`ADMIN`
- **请求体**：无

**说明**：清理旧向量后重新执行向量化（异步）。

**路径参数**：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | long | 是 | 知识库 ID |

**成功响应（HTTP 200）**：`data` 为当前知识库对象。

**失败响应**：

| 错误码 | 说明 |
|---|---|
| `RESOURCE_NOT_FOUND` | 知识库不存在 |
| `KNOWLEDGE_BASE_PROCESSING` | 知识库正在向量化处理（状态为 `UPLOADING`/`PROCESSING` 时不允许） |
| `AUTH_UNAUTHORIZED` / `RESOURCE_FORBIDDEN` | 未认证 / 非 ADMIN |

## 七、Skill 模块（全部要求 ADMIN）

### 接口 9：创建 Skill

- **路径**：`POST /api/skills`
- **鉴权**：`ADMIN`
- **请求头**：`Authorization: Bearer <token>`、`Content-Type: application/json`

**请求体**：

| 字段 | 类型 | 必填 | 说明 | 校验规则 | 示例 |
|---|---|---|---|---|---|
| `name` | string | 是 | Skill 名称 | 非空；长度 ≤ 128 | `售后问答` |
| `description` | string | 否 | Skill 描述 | 长度 ≤ 500 | `处理售后咨询` |
| `content` | string | 是 | Skill 配置/实现内容 | 非空；长度 ≤ 10000 | `向用户提供售后帮助` |
| `knowledgeBaseIds` | long[] | 是 | 关联知识库 ID 列表 | 非空；≥1 项 | `[1, 2]` |

**过程说明**：要求所有关联知识库存在且为 `READY`；Skill 主体与关联关系同一事务写入，状态固定 `ACTIVE`、版本固定 `1.0`。知识库为全局共享资源。

**成功响应（HTTP 200）**：`data` 为 `SkillResponse`。

```json
{
  "code": "SUCCESS",
  "message": "success",
  "data": {
    "id": 3,
    "name": "售后问答",
    "description": "处理售后咨询",
    "content": "向用户提供售后帮助",
    "status": "ACTIVE",
    "version": "1.0",
    "knowledgeBaseIds": [1, 2],
    "createdAt": "2026-10-12T10:30:00"
  },
  "traceId": "abc"
}
```

**失败响应**：

| 错误码 | 说明 |
|---|---|
| `VALIDATION_FAILED` | 请求体校验失败（含 `knowledgeBaseIds` 为空） |

### 12.2 JavaScript（fetch）

```javascript
async function loginOrCall() {
  const login = await fetch('/api/auth/login', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ username: 'admin', password: 'secret123' })
  });
  const { data } = await login.json();
  const token = data.token;

  const chat = await fetch('/api/digital-employees/4/chat', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json', 'Authorization': 'Bearer ' + token },
    body: JSON.stringify({ message: '午餐补贴标准是多少？' })
  });
  const body = await chat.json();
  if (body.code === 'SUCCESS') {
    console.log(body.data.reply);
  }
}
```

### 12.3 Python（requests）

```python
import requests

base = 'http://localhost:8080'

def call(path, token=None, json_body=None, files=None, method='POST'):
    headers = {}
    if token:
        headers['Authorization'] = f'Bearer {token}'
    resp = requests.request(method, base + path, headers=headers, json=json_body, files=files)
    body = resp.json()
    if body.get('code') != 'SUCCESS':
        raise RuntimeError(body.get('code'), body.get('message'))
    return body.get('data')

token = call('/api/auth/login', json_body={'username': 'admin', 'password': 'secret123'})['token']
# 上传知识库
files = {'file': ('guide.md', open('guide.md', 'rb').read())}
call('/api/knowledge-bases', token=token, files=files)
# 对话
msg = call('/api/digital-employees/4/chat', token=token, json_body={'message': '午餐补贴标准是多少？'})
print(msg['reply'])
```

### 12.4 错误处理要点

- 无论 HTTP 200 是否成功，都以响应体 `code == "SUCCESS"` 判断成功。
- 使用响应体 `traceId` 或响应头 `X-Trace-Id` 关联日志排查问题。
- 受保护接口先登录获取 token，并在后续请求头携带 `Authorization: Bearer <token>`。

## 十三、特别说明

- **HTTP 状态码语义**：本项目业务成败均以 `code` 字段表达，HTTP 恒为 200；不要依赖 401/403 判断未授权，而应读取 `AUTH_UNAUTHORIZED` / `RESOURCE_FORBIDDEN`。
- **资源共享**：知识库、Skill、数字员工为全局共享资源，接口不返回也不接受 `owner_id`，列表不做按创建人过滤。
- **审计字段**：`created_by`、`updated_by`、`released_by` 等由服务端从认证上下文写入，请求体不接受也不信任此类字段。
- **上传类型**：配置层面允许 `txt/md/pdf/docx`，但解析阶段仅 `txt/md` 可成功，`pdf/docx` 会进入 `FAILED` 并记录原因（见 `docs/API_SPEC.md` 与已知问题 DEF-003）。
- **对话非持久化到审计**：预览对话内容落库于会话/消息表，但**不进审计日志**。
- **版本发布不可变**：发布生成不可变配置快照；回滚通过新增生效记录实现，不修改历史快照。
