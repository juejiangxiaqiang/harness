# 项目需求

## 1. 目标

为管理员提供 Harness 后端管理能力，用于维护全局共享的知识库、Skills 和数字员工，并将数字员工发布为普通用户可使用的版本。当前项目是管理后台，不提供普通用户侧的数字员工运行或对话界面。

## 2. 用户与权限

系统用户分为管理员和普通用户。所有账号均需认证；授权按角色和操作执行，不按资源创建者隔离，因为知识库、Skills 和数字员工都是全局共享资源。

| 操作 | 管理员 | 普通用户 |
|---|---:|---:|
| 登录、退出登录 | 是 | 是 |
| 上传和查看共享知识库 | 是 | 否 |
| 创建和查看共享 Skills | 是 | 否 |
| 创建、查看和发布数字员工 | 是 | 否 |
| 预览页与数字员工实时对话（管理验证用途） | 是 | 否 |
| 使用已发布数字员工 | 管理验证用途 | 是 |

当前管理后台面向管理员，管理接口必须要求管理员角色。普通用户使用数字员工的运行或对话能力属于独立用户端或运行时服务，不在当前项目的管理接口范围内。

公开注册不得允许客户端自行指定管理员角色，也不得通过注册流程自助提升权限。管理员账号通过受控初始化或授权流程创建。

知识库、Skill、数字员工及发布版本不设置用户所有者。创建人、更新人和发布人仅用于审计，不构成资源访问隔离条件。

## 3. 功能需求

### 3.1 注册

- 注册或初始化流程创建账号，并由服务端策略确定角色。
- 账号必须唯一。
- 密码不得以明文保存。
- 公开请求不得指定或修改管理员角色。
- 注册成功后返回明确的成功结果。
- 注册失败时返回统一错误码。
- 实现说明：公开注册固定创建 `USER` 角色；管理员通过受控初始化创建（启动时按 `harness.bootstrap-admin.username/password` 环境变量幂等创建）。

### 3.2 登录

- 用户使用账号和密码登录。
- 登录成功后返回身份凭证。
- 密码错误、账号不存在、账号禁用需要返回可区分的业务错误。
- 受保护接口必须校验身份凭证。

### 3.3 退出登录

- 用户主动退出登录。
- 服务端应使当前凭证失效，或采用项目统一的无状态凭证失效策略。
- 重复退出不应导致系统异常。
- 实现说明：退出登录吊销当前凭证（数据库侧标记吊销），重复退出幂等；凭证仅保存 SHA-256 哈希，可配置有效期。

### 3.4 知识库

- 管理员可以上传全局共享知识库文件。
- 系统保存文件元数据和处理审计信息，不设置个人所有者。
- 系统校验文件名称、类型、大小和上传结果。
- 管理员可以查看和管理共享知识库列表。
- 知识库上传后必须经过文档解析、文本切分、向量化和向量数据库写入。
- 上传成功后自动创建向量化任务并异步执行；支持对已就绪/失败的知识库重新处理（先清理旧向量再重新向量化）。
- 向量模型和向量数据库优先通过 Spring AI 统一接入，业务代码不绑定具体厂商。
- 知识库应具备可追踪状态，例如 `UPLOADING`、`PROCESSING`、`READY`、`FAILED`。
- 只有向量化处理完成且状态为 `READY` 的知识库，才能被 Skill 选择。
- 向量化任务应具备幂等键、有限次数重试（指数退避）、失败原因记录与状态查询；向量写入未完整成功时不得标记为 `READY`。

### 3.5 Skills

- 管理员可以新增 Skill。
- Skill 至少包含名称、描述、版本或内容配置。
- 管理员可以查看共享 Skill 列表。
- Skill 的内容应经过基本格式校验。
- 创建 Skill 时可以选择一个或多个知识库。
- Skill 与知识库是多对多关系。
- 只有状态为 `READY` 的共享知识库，才能被 Skill 选择。

### 3.6 数字员工

- 管理员可以新增数字员工。
- 数字员工至少包含名称、描述、系统提示词和关联 Skills。
- 创建数字员工时可以选择一个或多个 Skill。
- 创建数字员工时不直接选择知识库；数字员工使用的知识库由所选 Skill 间接提供。
- 数字员工与 Skill 是多对多关系。
- 管理员可以查看数字员工列表和发布状态。
- 数字员工应有草稿和发布状态。
- 只有满足发布校验条件的数字员工才可以发布。

### 3.7 发布数字员工

- 发布前校验名称、提示词、模型配置和 Skills 等必填项。
- 发布前校验所选 Skills 是否存在、可用，并且其关联知识库均已完成向量化。
- 发布成功后生成可追踪的发布版本。
- 已发布版本应保留发布时间和发布人。
- 发布失败时保留失败原因。
- 已发布内容的变更不应静默修改历史发布版本。
- 普通用户只能使用已发布的数字员工，不得调用管理接口创建或修改数字员工、Skills、知识库。

### 3.8 管理端预览对话

管理端在数字员工预览页提供管理员专用的**实时对话验证**能力，用于发布前/发布后核对数字员工的回复效果。

- 管理员可在数字员工预览页「预览」页签中与该数字员工进行实时对话。
- 对话基于数字员工当前配置（系统提示词、模型配置及关联 Skills 展开的知识库）实时检索并生成回答，不依赖本地演示数据。
- 回复以一次性 JSON 返回（非流式），界面展示发送中指示器、快捷提问与新建/切换会话能力。
- 对话面向管理验证用途，仅限已认证的 `ADMIN` 角色调用；普通用户不得使用该对话能力。
- 会话与消息持久化到数据库（`preview_conversation`/`preview_message` 表），提供**对话历史查询**接口，管理员可查看会话列表与消息。
- 对话过程中摄入的问题与生成内容**不进入审计日志**，仅用于管理验证（会话/消息落库用于历史回看）。
- 当数字员工无可用的 READY 知识库或资源不可用时，对话返回明确业务错误并可重试；对话模型未配置时返回 `CHAT_PROVIDER_NOT_CONFIGURED`。

## 4. 非功能需求

- 所有受保护接口必须进行身份认证和角色权限校验。
- 管理后台的知识库、Skill、数字员工及发布管理接口必须要求管理员角色。
- 共享资源不能通过创建用户或请求参数形成个人资源隔离。
- 关键操作必须记录结构化日志。
- 外部 HTTP 调用统一使用 `ApiClient`。
- 向量模型和向量数据库的接入统一通过 Spring AI 适配。
- 知识库向量化处理应支持失败重试、状态查询和失败原因记录。
- 新功能必须包含 JUnit 5 测试，目标覆盖率不低于 80%。
- 单文件不超过 300 行，单方法不超过 50 行。
- 接口错误返回格式必须统一。
