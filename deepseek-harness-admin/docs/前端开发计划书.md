# 前端开发计划书

> 适用范围：`deepseek-harness-admin` 管理后台（管理员侧）前端
> 定位：面向管理员的知识库、Skills、数字员工统一管理界面，含登录、上传、创建、发布、预览与回滚能力。
> 后端：`deepseek-harness-admin-backend-code`（Spring Boot 4.0.x，已按阶段 S0-S7 全部完成，本计划书前端对接其管理 API）。
> 设计依据：`docs/VISUAL_DESIGN.md` 视觉方案；`images/design/` 下 6 个 HTML 原型（login / knowledge-base / create-skill / create-employee / employees / employee-preview）与 `style.css`。

---

## 1. 项目概述

### 1.1 目标

为管理员提供一套 **专业、可信赖、克制、效率优先** 的 Web 管理界面，完成知识库上传与向量化状态跟踪、Skill 创建与知识库关联、数字员工创建与发布、发布版本预览与回滚等核心操作，并将设计稿（含视觉方案与 HTML 原型）落地为可复用、可测试、可上线的前端工程。

当前范围明确为 **管理后台**，不含普通用户侧的运行与对话界面。管理端的**预览对话**在预览页「预览」页签提供，用于管理员与数字员工的实时对话验证（基于数字员工当前配置检索生成，一次性返回渲染，含历史会话），属管理验证用途，不作为用户端正式产品。

### 1.2 功能范围

| 模块 | 页面 | 核心能力 |
|---|---|---|
| 认证 | 登录 | 账号密码登录、记住我、错误内联提示、凭据注入 |
| 知识库 | 知识库列表 + 上传弹窗 | 上传（拖拽/选择）、类型/大小校验、状态筛选、进度、重新向量化、删除 |
| Skills | Skill 创建（附列表） | 表单填写、内容校验、仅选 `READY` 知识库、多对多关联 |
| 数字员工 | 列表 / 创建 / 预览 | 创建与 Skill 多选、发布校验、发布、版本历史、回滚、实时对话验证（一次性返回） |
| 全局 | App 外壳 | 侧边栏、面包屑、页面标题区、搜索、Toast、二次确认、骨架屏、空态 |

### 1.3 非功能目标

- 全部页面覆盖加载、空、错误态；关键操作有防重复提交与结果反馈。
- 与 `VISUAL_DESIGN.md` 设计令牌一致，全站复用统一令牌与组件。
- LCP、布局稳定性、可达性（键盘、对比度、动效降级）满足第 6 章指标。
- 前端代码质量与后端规范对齐（单一职责、有限规模、必配测试）。

## 2. 技术栈选型

| 类别 | 选型 | 版本基线 | 选型理由 |
|---|---|---|---|
| 框架 | Vue 3 (Composition API + `<script setup>`) | 3.5.x | 组件化、组合式开发效率高，契合原型多控件页面 |
| 语言 | TypeScript | 5.x | 严格类型，配合后端统一 DTO 降低联调错误 |
| 构建 | Vite | 6.x | 开发热更新快，产物分包便于性能优化 |
| UI | Element Plus（主题变量覆盖） | 2.x | 覆盖胶囊按钮、表单、弹窗、表格、消息提示等组件 |
| 状态 | Pinia | 2.x | 最小化全局状态，承载用户会话与全局反馈 |
| 路由 | Vue Router | 4.x | 权限守卫 + 布局嵌套路由 |
| HTTP | Axios（封装 ApiClient） | 1.x | 统一响应解码、`traceId`、携带 Bearer、错误码映射 |
| 测试 | Vitest + Vue Test Utils + Playwright | 最新稳定 | 单测/组件测试 + E2E 验收 |
| 代码质量 | ESLint + Prettier + lint-staged + Husky | 最新稳定 | 提交前自动检查与格式化 |
| 发布 | Nginx 静态部署 + `/api` 反向代理 | - | 前后端分离，产物含 gzip/缓存配置 |

### 2.1 设计令牌映射

将 `VISUAL_DESIGN.md` 的视觉方案落地为工程级设计令牌：

- 以 CSS 变量定义色彩（`primary #5B6BF5`、中性灰阶、四类状态色、三层阴影）、间距（8px 基数）、圆角（胶囊/6/12/16）、字号字重。
- 通过 Element Plus 主题变量（如 `--el-color-primary`) 覆盖为 `primary`，保证组件库与设计原生对齐。
- 全站禁止散落魔法色值，统一引用令牌。

### 2.2 目录规划

```text
src/
├── api/            # ApiClient 与各模块接口封装（auth/knowledgeBase/skill/digitalEmployee）
├── assets/         # 样式基础、设计令牌、图标
├── components/     # 通用组件（状态标签、上传、胶囊筛选、二次确认、骨架屏等）
├── layouts/        # AppShell（侧边栏 + 面包屑 + 标题区）
├── router/         # 路由与权限守卫
├── stores/         # Pinia（user / app）
├── types/          # 类型定义（对齐后端 DTO 与枚举）
├── views/          # 页面（login / knowledge-bases / skills / digital-employees / preview）
└── utils/          # 格式化、请求、校验等工具
```

## 4. 阶段性开发计划

> 说明：后端已就绪，前端按其 API 并行推进。时间节点为**指示性排期**，实际以各阶段验收完成情况驱动，前一阶段未验收通过不进入下一阶段。

### 4.1 P1 工程基线与登录认证

**目标**：建立可运行工程骨架、统一设计令牌与 App 外壳，上线登录链路与全局请求/错误处理，为后续模块提供一致底座。

#### 功能模块
- 工程脚手架（Vite + Vue3 + TS + ESLint + Prettier + Husky/lint-staged）。
- 设计令牌体系与 `style.css` 原型样式迁移为令牌化组件样式。
- AppShell 布局（侧边栏、面包屑、页面标题区、用户区）。
- 登录页（表单、校验、记住我、加载态、内联错误）。
- Axios `ApiClient`：统一响应解码、`traceId` 透传、Bearer 注入、401/403 处理、错误码映射（对照 `API_SPEC.md`）。
- 路由权限守卫 + Pinia 用户会话。

#### 开发任务
1. 初始化工程并接入校验与格式化工具。
2. 建立设计令牌与全局样式，覆写 Element Plus 主题变量。
3. 实现 AppShell 与占位路由。
4. 封装 `ApiClient` 与错误处理。
5. 实现登录页并接通 `POST /api/auth/login`，完成登出与守卫。
6. 脚手架级单测与 E2E 冒烟。

#### 时间节点（指示性）
第一周完成脚手架、令牌、AppShell；第二周完成登录链路与守卫，两周结束时对齐 API 联调。

#### 验收流程
- 参与人员：前端开发、后端/接口负责人（联调）、架构评审（分层与规范）、测试。
- 验收步骤：
  1. 拉取工程执行 `npm install` + `npm run lint` + `npm run build`，确认无错误。
  2. 配置本地后端环境，登录、登出、刷新令牌有效性人工验证。
  3. 故意输入错误凭据，确认展示内联错误且不泄漏堆栈。
  4. 未登录访问受保护路由，确认自动跳转登录。
  5. 用 Playwright 执行登录 E2E 用例。
- 验收工具：Lighthouse（性能初检）、Playwright、ESLint。

### 4.2 P2 知识库与 Skills 管理

**目标**：完成知识库上传与向量化状态跟踪、Skill 创建与 `READY` 知识库多选关联，实现资源管理主链路。

#### 功能模块
- 知识库列表：状态筛选（全部/待处理/处理中/已就绪/失败）、搜索、分页、进度展示。
- 上传弹窗：拖拽/点击选文件、类型与大小校验、文件列表、上传后自动触发向量化。
- 状态标签与重试/删除（含二次确认）。
- Skill 列表 + 新建 Skill：表单校验、右侧 `READY` 知识库卡片多选、禁选非就绪项。

#### 开发任务
1. 封装知识库接口（上传、列表、详情、重新向量化）与 Skill 接口（创建、列表、详情）。
2. 实现知识库列表、状态筛选、分页与空/加载态。
3. 实现上传弹窗与类型/大小前端预校验（对齐后端限制）。
4. 实现状态标签、进度条、重新向量化/删除二次确认。
5. 实现创建 Skill 页面及 `READY` 知识库多选面板。
6. 组件与接口的单测、关键流程 E2E。

#### 时间节点（指示性）
第三周完成知识库模块；第四周完成 Skills 模块与联调。

#### 验收流程
- 参与人员：前端开发、后端/接口负责人、产品（核对交互）、测试。
- 验收步骤：
  1. 上传合法与非法文件（当新型/超限），确认前端预校验与服务端校验一致，非法项有失败原因展示。
  2. 上传后观察 `UPLOADING → PROCESSING → READY/FAILED` 状态与进度刷新。
  3. 状态筛选、搜索、分页人工验证。
  4. 创建 Skill 时确认仅可勾选 `READY` 知识库，非就绪项禁用且提示原因（`KNOWLEDGE_BASE_NOT_READY`）。
  5. 必填与格式校验、失焦校验、删除二次确认人工验证。
  6. Playwright 覆盖上传与建 Skill 主链路。
- 验收工具：Playwright、浏览器 DevTools（Network/响应解码）、Lighthouse。

### 4.3 P3 数字员工与发布预览

**目标**：完成数字员工创建、发布校验、版本管理与对话预览，形成"创建—发布—回滚—预览"完整闭环。

#### 功能模块
- 数字员工列表（卡片/筛选）。建议同步确认是否具备业务分类字段，未具备则不展示分类筛选，避免与后端数据模型不符。
- 创建数字员工：基础信息、系统提示词、模型配置（模型/温度/上下文长度）、Skill 卡片多选。
- 发布校验结果区：成功/失败原因列表，失败禁用发布。
- 发布（二次确认，生成版本）、版本历史、回滚（生成新生效记录，不改历史快照）。
- 数字员工预览：左侧信息面板 + 右侧对话验证（气泡、输入区、快捷提问、发送中指示器、一次性返回渲染、历史会话加载与切换/新建） + 版本历史/配置页签。

#### 开发任务
1. 封装数字员工接口（创建、列表、详情、发布、回滚）与**管理端对话接口**（`POST /api/digital-employees/{id}/chat`、会话/消息历史接口）。
2. 实现数字员工列表与创建页（含 Skill 多选、模型配置）。
3. 实现发布前置校验与失败原因展示（对齐 `DIGITAL_EMPLOYEE_NOT_PUBLISHABLE`）。
4. 实现版本历史、发布、回滚交互与二次确认。
5. 实现预览页对话验证组件（气泡、输入区、快捷提问、发送中指示器、一次性渲染、历史会话切换与新建）与版本信息面板。
6. 关键链路单测与 E2E。

#### 时间节点（指示性）
第五周完成列表与创建；第六周完成发布与预览，结束全部页面主体。

#### 验收流程
- 参与人员：前端开发、后端/接口负责人、产品、测试、管理员代表（终端体验）。
- 验收步骤：
  1. 创建数字员工，确认请求体不含 `knowledgeBaseIds`，数据由 Skills 间接确定。
  2. 选择含未就绪知识库的 Skill 发布，确认校验拦截并红字列出原因；修复后发布成功并生成版本。
  3. 版本历史展示发布人/时间/版本，回滚生成新生效记录且历史快照不变。
  4. 预览页对话验证：输入问题与快捷提问得到一次性实时回复，发送中指示器、历史会话切换与新建正常；普通用户不可调用对话接口（前端按 403 处理）。
  5. 权限校验：确认普通用户调用管理接口被拒（前端 403 处理）。
  6. E2E 覆盖"创建—发布—回滚—预览"全链路。
- 验收工具：Playwright、DevTools、Lighthouse。

### 4.4 P4 质量、验收与上线

**目标**：全站质量收敛，达到可上线状态（性能、兼容、可达性、测试与代码质量达标），完成预发布验证。

#### 功能模块
- 全站走查：加载/空/错误态、表单校验、二次确认、Toast、防重复提交。
- 性能优化：路由懒加载、分包、gzip、图片与骨架屏优化。
- 可达性与响应式：键盘可达、焦点环、对比度、`prefers-reduced-motion`、断点降级。
- 测试补齐：组件/接口单测、E2E 覆盖核心路径，覆盖率达标。
- 构建与部署：Nginx 产物、`/api` 反向代理、环境变量、CI 流水线。

#### 开发任务
1. 全站一致性走查并修复缺陷。
2. 性能与可达性专项优化并复测 Lighthouse。
3. 补齐测试用例与覆盖率报告。
4. 配置构建产物与部署（含 gzip、缓存、`/api` 代理）。
5. 预发布环境部署并完成回归。

#### 时间节点（指示性）
第七至八周完成质量收敛、回归与预发布部署。

#### 验收流程
- 参与人员：前端开发、测试、运维（部署）、产品、管理员代表。
- 验收步骤：
  1. 在预发布环境跑完整 E2E 与手工回归用例。
  2. Lighthouse 关键页面复测，确认在阈值内。
  3. 主浏览器 + 目标分辨率 + 网络降级场景走查。
  4. 确认覆盖率、ESLint、构建产物、敏感信息不泄漏。
  5. 输出上线条目并签字通过。
- 验收工具：Playwright、Lighthouse、CI 报告（Vitest/JaCoCo 前端并行）、DevTools。

## 6. 验收标准

### 6.1 功能完整性

- 第 3 章页面对应的接口全部接通；成功、校验失败、权限拒绝、异常路径均有明确前端反馈。
- 每个列表页具备加载（骨架屏）、空态（引导）与错误态（重试）。
- 关键操作（上传、删除、发布、回滚）具备防重复提交与二次确认。
- 状态映射完整（知识库 `UPLOADING/PROCESSING/READY/FAILED`；发布 `SUCCESS/FAILED`），枚举展示与 `API_SPEC.md` 一致。
- 分页参数 `page/size`、单页上限 100 与后端约定一致。

### 6.2 界面一致性（对照 `VISUAL_DESIGN.md` 第 8 章核对表）

- 全站复用设计令牌（色彩 `#5B6BF5` 主色、间距 8px 基数、三层阴影），无散落魔法值。
- 布局沿用"侧边栏 + 主内容区"，导航选中态浅蓝底 + 左侧色条。
- 胶囊按钮、圆形渐变文字图标、细边框卡片、下划线激活标签跨页复用。
- 状态标签配色（灰/蓝/绿/红）与第二版设计一致，不使用浅色文字+浅色底。
- 全站动效统一 0.2s ease；`prefers-reduced-motion` 下关闭呼吸/跳动。

### 6.3 性能指标

| 指标 | 阈值 |
|---|---|
| 首屏内容绘制（LCP） | ≤ 2.5s（4G/桌面） |
| 交互响应（INP） | ≤ 200ms |
| 布局稳定性（CLS） | ≤ 0.1 |
| Lighthouse（性能/可达性/最佳实践） | 各 ≥ 90 |
| 首屏包体积（gzip 后） | 减小至目标范围，关键路由按需加载 |
| 接口数据面（p95 感知） | 列表/详情正常同步返回；异步任务字段轮询不卡 UI |

### 6.4 兼容性要求

- 浏览器：Chrome、Edge 最近两个稳定大版本；Firefox 最近两个稳定大版本；Safari 最近两个稳定大版本。
- 分辨率/断点：≥1440 默认布局、1200-1440 保持 4 列、768-1200 减至 2-3 列、<768 侧边栏收起为抽屉图标栏。
- 可达性：正文对比度 ≥ 4.5:1；所有交互元素支持 Tab 聚焦并有可见焦点环；表单错误可被辅助技术感知。
- 降级：`prefers-reduced-motion` 覆盖动效；异步失败有明确重试入口。

### 6.5 代码质量规范

- TypeScript 严格模式；`tsserver`/构建无类型错误。
- ESLint 无 Error 级别问题，提交前通过 lint-staged 检查。
- 职责与规模：组件与文件保持单一职责；单文件 ≤ 300 行、单函数 ≤ 50 行（对齐后端 `AGENTS.md` 规范）。
- 注释与文档：文件头、类/函数 Javadoc 风格说明职责、参数与返回；业务分支与校验写中文行内注释；与 `docs` 语言一致。
- 日志与安全：不向日志或页面输出密码、令牌、API Key、敏感文件内容；错误信息不暴露堆栈。
- 测试：组件/接口单测覆盖率 ≥ 80%，覆盖成功、校验失败、权限拒绝、异常路径；核心路径 E2E 通过。

## 7. 风险与依赖

| 风险/依赖 | 应对 |
|---|---|
| 后端模型缺少业务分类字段（数字员工表无分类/标签列） | 已在 P3 标注：不擅自增加业务分类筛选，需先对齐需求与数据模型；如需新增应回归后端 |
| 异步向量化任务的状态轮询频率 | 采用轮询 + 状态变更驱动，降低无关请求，避免阻塞 UI |
| 上传体积大导致请求超时 | 前端超时调优、分片或进度提示，配合后端限制 |
| 组件库样式与设计令牌差异 | 通过 Element Plus 主题变量集中覆盖并统一走查 |
| 浏览器兼容差异 | 建立目标浏览器矩阵，P4 专项回归 |
