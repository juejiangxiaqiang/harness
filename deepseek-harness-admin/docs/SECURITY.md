# 安全规范

## 1. 适用范围

当前项目是管理员使用的后端管理服务。安全重点是保护管理接口、全局共享资源、知识库文件、模型配置和发布能力。

普通用户只能使用已发布的数字员工，不得访问本项目的管理接口。

## 2. 身份认证

- 所有管理接口必须要求登录。
- 登录成功后返回项目统一的身份凭证。
- 密码只能保存为安全哈希，禁止明文保存和日志输出。
- 认证失败、凭证过期和账号禁用必须返回统一错误。
- 退出登录应使当前凭证失效，或执行项目约定的无状态凭证失效策略。
- 登录接口应具备基本的失败次数限制和防暴力破解策略。

## 3. 角色授权

角色至少包括：

- `ADMIN`：访问管理后台，上传知识库，创建和维护 Skills、数字员工，发布和回滚数字员工。
- `USER`：不能访问管理 API，只能在独立用户端使用已发布数字员工。

约束：

- 角色从认证上下文获取，不能信任请求体中的角色字段。
- 公开注册不得自助创建 `ADMIN`。
- 管理员角色只能通过受控初始化或授权流程授予。
- 每个管理接口必须明确所需角色。

## 4. 资源安全

- 知识库、Skills 和数字员工是全局共享资源，不设置个人所有权。
- 资源访问不按创建人过滤，但所有写操作都必须校验管理员角色。
- 创建人、更新人和发布人只用于审计。
- 删除、禁用或重新处理资源前，必须检查其关联关系和已发布版本引用。
- 已发布版本使用不可变配置快照，不受草稿后续修改影响。

## 5. 文件上传安全

- 限制允许的文件类型、扩展名和大小。
- 不信任客户端传入的文件名和 MIME 类型，应进行服务端校验。
- 文件名进行规范化，防止路径穿越。
- 原始文件与解析后的内容分开存储。
- 文件存储使用随机或不可预测的存储键。
- 解析失败、超时和恶意内容需要进入 `FAILED` 状态。
- 管理接口不得直接返回服务器真实文件路径。

## 6. 敏感信息

以下信息不得出现在普通日志中：

- 密码和身份凭证
- 模型 API Key
- 向量数据库连接密码
- 数据库密码
- 完整的敏感提示词或上传文件内容

密钥通过环境变量、密钥管理服务或部署平台 Secret 注入，不写入 Git 仓库。

## 7. 输入与接口安全

- 所有请求参数使用校验注解或领域校验。
- 列表接口限制分页大小，避免一次性查询大量数据。
- 文件上传、登录和管理写接口应配置限流。
- 统一异常处理器不得向客户端暴露堆栈和内部连接信息。
- 外部 HTTP 调用使用统一 `ApiClient`，配置连接和读取超时。
- 关键管理操作记录操作者、资源 ID、操作结果和 traceId。

## 8. 安全测试

必须覆盖：

- 普通用户访问管理接口返回禁止访问。
- 注册请求不能提升为管理员。
- 无效凭证不能访问受保护接口。
- 越权修改、删除、发布请求被拒绝。
- 非法文件类型、超大文件和恶意文件名被拒绝。
- 敏感字段不会出现在响应和日志中。
