# 可观测性规范

## 1. 目标

保证管理员可以看到请求状态、知识库向量化任务状态、发布结果和外部依赖健康情况。

## 2. 日志

统一使用 SLF4J 结构化日志。每条关键日志建议包含：

- `timestamp`
- `level`
- `traceId`
- `requestId`
- `userId`
- `role`
- `operation`
- `resourceType`
- `resourceId`
- `result`
- `durationMs`

**实现说明**：请求级 `traceId` 由 `TraceIdFilter` 生成/透传（请求头 `X-Trace-Id`）并写入 MDC，日志与统一响应均携带；认证拦截器将 `userId`/`role` 写入 MDC。登录、上传、创建、发布、回滚、向量化成功/重试/最终失败等关键操作均以结构化参数记录。禁止使用 `System.out` 和 `printStackTrace`。

日志级别建议：

- `INFO`：登录、上传、创建、发布、回滚等关键成功操作。
- `WARN`：重试、限流、资源状态异常和可恢复失败。
- `ERROR`：任务最终失败、数据库异常、向量数据库异常和外部服务不可用。

## 3. 关键指标

### HTTP 指标

- 请求总数
- 按接口和状态码统计的请求数
- P95/P99 响应时间
- 4xx、5xx 错误率
- 登录失败次数
- 管理接口拒绝次数

### 知识库指标

- 上传成功数和失败数
- `UPLOADING`、`PROCESSING`、`READY`、`FAILED` 数量
- 向量化任务耗时
- 文档片段数量
- Embedding 调用耗时和失败率
- 向量数据库写入耗时和失败率
- 重试次数和最终失败数

### 发布指标

- 发布成功数和失败数
- 发布校验失败原因
- 发布耗时
- 当前生效版本
- 回滚次数

## 4. 健康检查

健康检查至少包括：

- 应用进程
- MySQL 连接
- 向量数据库连接
- 向量模型服务连通性
- 原始文件存储可用性

健康检查不得返回密码、API Key、连接字符串等敏感信息。

**实现说明**：提供 `GET /api/health`（统一响应结构）与 actuator 健康端点；`StorageHealthIndicator` 检查知识库文件存储目录可写性并纳入 actuator 健康检查（Boot 4 `spring-boot-health` 模块 API）。

## 5. 告警

建议对以下情况告警：

- 5xx 错误率持续升高
- 登录失败异常增加
- 向量化任务长时间停留在 `PROCESSING`
- 向量化最终失败数超过阈值
- 向量模型调用连续失败
- 向量数据库不可用
- MySQL 连接池耗尽
- 磁盘或文件存储空间不足

状态未变化且未达到告警条件时，不重复发送告警。

## 6. 审计

以下操作必须记录审计事件：

- 登录和退出登录
- 管理员创建或修改 Skill
- 上传、重新处理或删除知识库
- 创建或修改数字员工
- 发布和回滚数字员工
- 修改用户角色

审计记录至少包含操作者、角色、操作时间、资源类型、资源 ID、操作结果和失败原因。
