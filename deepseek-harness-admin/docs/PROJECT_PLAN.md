# 项目计划

本文档将 Harness 管理后台的目标拆分为可交付阶段。每个阶段给出功能范围、验收方法和质量门槛，阶段按依赖顺序推进，前一阶段未通过验收不进入下一阶段。

## 1. 阶段总览

| 阶段 | 主题 | 主要交付 | 进入下一阶段的条件 |
|---|---|---|---|
| S0 | 工程基线 | 工程骨架、构建、规范、检查脚本 | 构建通过，基线检查脚本可运行 |
| S1 | 用户与权限 | 注册、登录、退出、角色授权 | 权限边界测试全部通过 |
| S2 | 知识库上传 | 上传、文件存储、状态管理 | 上传与状态流转验收通过 |
| S3 | 向量化 | 解析、切分、Embedding、向量写入、任务治理 | 向量化与幂等重试验收通过 |
| S4 | Skills | Skill 创建与知识库关联 | 关联校验与状态约束验收通过 |
| S5 | 数字员工 | 数字员工创建与 Skill 关联 | 关联与权限验收通过 |
| S6 | 发布与回滚 | 发布校验、版本快照、回滚 | 发布与回滚验收通过 |
| S7 | 质量与上线 | 覆盖率、可观测性、安全、部署 | 上线检查清单全部通过 |

## 2. S0 工程基线

### 目标

建立可运行、可构建、可测试的工程骨架，并让硬性规范可以被自动检查。

### 功能范围

- 建立 Spring Boot 4.0.x 工程结构与 `pom.xml`。
- 按 `domain → config → mapper → service → controller` 建立包结构。
- 接入 MySQL 8.0、MyBatis-Plus 3.5.x、Spring AI 依赖与 BOM。
- 建立统一响应结构、统一异常处理器、`traceId`。
- 建立 SLF4J 结构化日志配置。
- 提供单元测试与集成测试的目录和基线示例。
- 提供基础健康检查接口。

### 验收方法

- 执行 Maven 构建，确认编译通过。
- 执行一次示例单元测试和一次示例集成测试，确认测试框架可用。
- 人工检查分层依赖方向，确认无反向依赖。
- 人工检查统一异常处理能把业务异常转换为统一错误结构。

### 质量门槛

- 依赖方向符合规范，无反向依赖。
- 统一响应和异常处理生效。
- 日志为结构化格式，无标准输出残留。

## 3. S1 用户与权限

### 目标

实现管理员与普通用户的账号体系，并保证管理接口的权限边界可靠。

### 功能范围

- 注册或受控初始化创建账号，服务端决定角色。
- 登录、退出登录、凭证校验。
- 管理员角色受控授予，公开注册不可自助提权。
- `ADMIN`/`USER` 角色授权拦截。
- 统一认证失败、无权限的业务错误码。

### 验收方法

- 单元测试覆盖账号唯一性、密码校验、角色边界。
- 集成测试覆盖普通用户调用管理接口返回禁止访问。
- 手工验证退出后访问受保护接口被拒绝。

### 质量门槛

- 权限相关测试全部通过。
- 不存在任何由请求体直接决定角色或操作者的路径。
- 认证失败路径不泄漏敏感信息。

## 4. S2 知识库上传

### 目标

实现共享知识库的上传、元数据管理和状态流转。

### 功能范围

- 管理员上传文件，保存元数据，不设置个人所有者。
- 文件类型、大小和名称校验。
- 原始文件存储位置可配置。
- 知识库状态管理：`UPLOADING`、`PROCESSING`、`READY`、`FAILED`。
- 知识库列表和详情查询。

### 验收方法

- 单元测试覆盖类型和大小校验、状态流转。
- 集成测试覆盖上传后可在共享列表中查看。
- 手工上传非法文件，确认被拒绝且记录失败原因。

### 质量门槛

- 非 `READY` 状态知识库不可被 Skill 关联。
- 上传记录和状态变化可追踪。
- 敏感文件内容和密钥不进入日志。

## 5. S3 向量化

### 目标

通过 Spring AI 完成知识库的向量写入，并保证任务可治理。

### 功能范围

- 文档解析和文本切分。
- 通过 `EmbeddingModel` 调用向量模型。
- 通过 `VectorStore` 写入向量数据库。
- 异步处理任务，支持状态查询、失败原因记录、有限次数重试。
- 任务幂等键和向量写入幂等 upsert。
- 知识库重新处理和向量清理规则。

### 验收方法

- 单元测试覆盖幂等键生成、重试与重试耗尽、失败状态。
- 集成测试覆盖 Spring AI Embedding 与 `VectorStore` 适配。
- 手工验证重复触发处理不会产生重复向量片段。
- 手工验证向量写入不完整时不会标记为 `READY`。

### 质量门槛

- 向量模型和向量数据库可替换，业务不绑定具体厂商。
- 重试为有限次数且带退避策略。
- 每次向量化都有可追踪的任务记录。

## 6. S4 Skills

### 目标

实现 Skill 管理及其与共享知识库的关联。

### 功能范围

- 管理员创建 Skill，校验名称、描述和内容格式。
- 创建 Skill 时可选择多个 `READY` 状态知识库。
- Skill 与知识库多对多关联维护。
- Skill 列表与详情查询。

### 验收方法

- 单元测试覆盖内容校验和多知识库关联。
- 集成测试覆盖关联非 `READY` 知识库时被拒绝。
- 手工验证缺少必填字段时创建失败。

### 质量门槛

- 关联关系有联合唯一约束。
- 资源关联不按创建人隔离。
- 关联校验逻辑集中在 Service 层。

## 7. S5 数字员工

### 目标

实现数字员工配置及其与 Skill 的关联。

### 功能范围

- 管理员创建数字员工，包含名称、描述、系统提示词和模型配置。
- 创建时可选择多个 Skill，不直接选择知识库。
- 数字员工与 Skill 多对多关联维护。
- 数字员工列表、详情和草稿/发布状态展示。

### 验收方法

- 单元测试覆盖多个 Skill 关联。
- 集成测试覆盖普通用户无法创建数字员工。
- 手工验证创建请求不接收 `knowledgeBaseIds`。

### 质量门槛

- 数字员工不直接关联知识库。
- 关联校验规则与发布校验规则保持一致。
- 控制器不包含业务规则。

## 8. S6 发布与回滚

### 目标

实现数字员工发布、版本快照和回滚。

### 功能范围

- 发布前校验名称、提示词、模型配置、Skills 及展开后的知识库状态。
- 生成不可变发布版本快照。
- 记录发布人、发布时间和版本号。
- 支持回滚到历史发布版本，回滚生成新的生效记录。
- 发布失败保留失败原因。

### 验收方法

- 单元测试覆盖发布前置校验、版本号生成和快照内容。
- 集成测试覆盖关联资源未就绪时发布被拒绝。
- 手工验证回滚不修改历史快照，并生成新生效记录。

### 质量门槛

- 任何一步失败不产生不完整发布结果。
- 发布与回滚均记录管理员、时间、版本和结果。
- 发布校验与运行使用的配置一致。

## 9. S7 质量与上线

### 目标

达到可上线质量，完成部署、监控和安全准备。

### 功能范围

- 单元测试、集成测试和端到端验收补齐。
- 结构化日志、关键指标、健康检查和告警配置。
- 密钥与凭证管理，不入库不入仓。
- 数据库迁移、备份恢复和回滚预案。
- 部署文档和配置说明。

### 验收方法

- 执行完整测试套件并确认覆盖率不低于 80%。
- 执行发布前检查清单。
- 在预发布环境完成一次部署、迁移、备份和恢复演练。
- 人工检查日志、指标和告警是否覆盖关键操作。

### 质量门槛

- 覆盖率不低于 80%。
- 无 `System.out` 和 `printStackTrace`。
- 外部 HTTP 调用均使用 `ApiClient`。
- 单文件不超过 300 行，单方法不超过 50 行。
- 关键管理操作均有审计记录。

## 10. 阶段通用要求

- 每个阶段开始前确认前一阶段验收已完成。
- 每个阶段交付时同步更新受影响的文档。
- 每个阶段新增功能必须配套 JUnit 5 测试。
- 每个阶段完成时执行发布前检查清单。
- 阶段内发现的需求变更先更新需求文档再实现。

## 11. 功能扩展说明：管理端预览对话

作为管理后台的一项管理验证能力，在数字员工预览页提供管理员与数字员工的实时对话（`3.8 管理端预览对话`）：

- 定位：管理员发布前/后验证数字员工回复效果，属「管理验证」用途，不替代普通用户端运行/对话服务（管理后台边界见 `ARCHITECTURE.md` 第 8 章）。
- 能力：基于数字员工当前配置（系统提示词、模型配置及关联 Skills 展开的 READY 知识库）实时检索生成，一次性返回回复；会话/消息落库并支持历史查询；对话接口仅限 `ADMIN`。
- 实现归属：后端新增预览对话模块（Service + 对话接口），前端在预览页「预览」页签对接；代码实现前先回读 `REQUIREMENTS.md 3.8`、`API_SPEC.md 第 5 章` 与 `HARNESS_DESIGN.md 第 10 章`。
- 验收：参照 `系统测试.md` TC-DE-PR-008/017~021 与 `TESTING.md`「管理端预览对话」章节，并同步更新文档。
